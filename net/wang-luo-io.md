# 网络IO

## 一次IO的两个阶段

### 阶段1

系统内核等待数据到达。主要为网卡或者磁盘接收数据放入到内核缓存区的过程。

### 阶段2

数据从系统内核拷贝到用户空间。主要是内核缓冲区数据拷贝到用户缓冲区的过程。

## 阻塞IO

默认的socket为阻塞模式

流程

* 你调用 read()；
* 内核说：“还没数据，等着吧”；
* 你的线程就睡着了；
* 数据到达后，内核拷贝到用户缓冲区，read() 才返回；
* 整个过程你啥也干不了。

阻塞点

* 等数据（阶段1）；
* 拷贝数据（阶段2）；
* 都在阻塞。

## 非阻塞IO

可以将socket设置成非阻塞模式，如果内核缓冲区没数据，那么立即返回 **-1**，并设置errno = EAGAIN

流程

* 你调用 read()；
* 如果没数据，内核马上返回 EAGAIN；
* 你只能自己反复调用（忙轮询）；
* 有数据后，read() 拷贝数据给你（这步仍然阻塞）。

阻塞点

* 等数据：不阻塞；
* 拷贝数据：阻塞；
* 但 CPU 可能被浪费在轮询上。

## IO多路复用

select/poll/epoll都属于IO多路复用。select属于全量扫描，poll也属于全量扫描，epoll属于回调方式。

流程

* 你先调用 select() 或 epoll\_wait()，让内核帮你等数据；
* 内核阻塞（阶段1 阻塞），但可以同时等多个 fd；
* 一旦有任意 fd 就绪（有数据到达），返回；
* 你再调用 read()，这时 read() 拷贝数据（阶段2 阻塞，但很快）；
* 所以线程只在“拷贝数据”时短暂阻塞。

阻塞点

* 阶段1：阻塞在 epoll\_wait()（等待事件）；
* 阶段2：阻塞在 read()（拷贝）；
* 但不会卡在无数据的连接上，提高利用率。

## 信号驱动

* 进程告诉内核：“这个 fd，如果能读/写了，请给我发个信号”
* 进程继续干别的事（不阻塞）
* 内核检测到fd就绪
* 内核向进程发送一个信号（如 `SIGIO`）
* 进程在信号处理函数里去 `read()`

## 异步IO

流程

* 你调用 aio\_read(fd, buf, ...)；
* 内核直接在后台完成等待 + 拷贝；
* 完成后通过信号/回调通知应用；
* 应用线程不阻塞。

阻塞点

* 阶段1：不阻塞；
* 阶段2：不阻塞；
* 真正的异步模型（很少被广泛用在网络 I/O）。

## 零拷贝是什么

零拷贝（Zero-Copy） 并不是说完全没有拷贝，而是指：在内核空间中尽量避免数据在内核与用户空间之间的多次复制。

如下是网络当中零拷贝的一个参考示例

### 传统 I/O 拷贝流程

读取和写入的过程

* 磁盘数据 -> 内核缓冲区
* 内核缓冲区 -> 用户缓冲区
* 用户缓冲区 -> 内核 socket 缓冲区
* socket 缓冲区 -> 网卡发送

一共发生了 4次数据拷贝

### 零拷贝过程

读取和写入的过程

* 磁盘数据 -> 内核缓冲区
* 内核缓冲区 -> 内核 socket 缓冲区
* socket 缓冲区 -> 网卡发送

一共发生了 3次数据拷贝

### Linux零拷贝提供了多种系统调用方法

mmap + write

sendfile()

splice() / tee()

sendmmsg() / recvmmsg()

## Netty当中的零拷贝

除了系统提供的一些零拷贝手段，Netty也有自己的逻辑层面的零拷贝技术。

主要就是对ByteBuf 的操作中，通过共享引用、切片、合并来避免额外复制。

主要方法有

```
slice()	                    生成原 ByteBuf 的子视图（共享内存，不复制数据）
duplicate()	            创建新的 ByteBuf 对象，指针独立但数据共享
compositeBuffer()	    聚合多个 ByteBuf，不进行物理拷贝
retain()/release()	    引用计数机制，确保共享内存安全
Unpooled.wrappedBuffer()    直接包装现有字节数组，不再复制
```
